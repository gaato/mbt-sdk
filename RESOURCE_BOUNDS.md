# Resource bounds

What a long-running SDK client, JSON-RPC connection, or Codex session can
accumulate, and what keeps each structure from growing without limit. The
rule: **every structure that grows with input from the network, a peer
process, or the number of requests, buckets, connections, or pending calls is
listed here with its bound**. A new one — an `@aqueue.Queue(kind=Unbounded)`,
a map keyed by ids or names that arrive from outside, a buffer filled from a
socket — needs a row before it ships.

A bound is either a limit the code enforces, or the rate of the input times
how long an entry lives, where both are themselves bounded. Rows of the second
kind say what that product is. Rows marked with a PR number describe behaviour
that PR introduced (#40, #43, #44, #47, #48, #49, #50, #51), so they can be checked against it.

**Every row of "Enforced limits" names a test that checks the bound**, in its
Tests column: a backticked file path, then the quoted names of that file's
tests, as in `` `jsonrpc/src/framer_wbtest.mbt`: "first", "second" ``. A test
counts only if it drives the structure to its limit and one past it, or pins a
default the row states; one that merely uses the feature does not.
`scripts/bounds_check.sh`, run by `scripts/gates.sh`, enforces the naming: it
fails when a row names no test or a named test is not declared in the named
file. Whether a named test really reaches the bound is checked in review. The
other tables describe where no limit is enforced, so they stay prose.

Scope: the hand-written modules `http` (with `http/sse` and `http/cookie`),
`http-async`, `sdk-runtime`, `jsonrpc`, `jsonrpc-async` and
`codex-app-server`. The generated SDKs (`openai`, `anthropic`, `github`)
appear only where they buffer responses or streams; they do so through
`sdk-runtime`, the transport the caller passes, and `@sse.each_event`. Test
helpers (`http/mock`, `http-async/mock`) record what a test feeds them and are
not listed.

## Bounded by rate and lifetime

| Structure | Grows with | Bound |
|---|---|---|
| Parked keep-alive connections (`http-async/src/pool.mbt`, `IdlePool::put`, `IdlePool::sweep`) (#43) | Distinct origins one transport talks to, times `max_idle_per_origin` (default 4); there is no cap across origins. Connections are parked and counted by origin and the proxy that reaches it (`http-async/src/proxy.mbt`, `Route::key`), but a transport routes each origin one way, so there are as many keys as origins | Eviction is lazy: every checkout and checkin closes the connections parked longer than `idle_max_ms` (default 10 s) across all origins and forgets emptied origins, but no timer runs, so after the last request they stay parked until the next request or `close()`. A connection over the per-origin cap is closed instead of parked. #43 parks a connection unless `Connection` carries `close` as a whole token |
| Rate-limit bucket gates (`sdk-runtime/src/rate_limit.mbt`, `WindowLimiter::join_gate`, `leave_gate`) | Requests holding or waiting on a bucket's gate | Requests in flight: an entry leaves when both its holder and waiter counts reach zero, including after a cancelled `acquire` (`errdefer`) |
| Rate-limit states (`sdk-runtime/src/rate_limit.mbt`, `WindowLimiter::sweep_states`, `acquire`) | Distinct bucket names with a recorded window | Eviction is lazy: a `release` sweeps expired states when the map has doubled since the last sweep (floor 64) or a minute has passed since it, and `acquire` drops its own bucket's expired state. No timer runs, so when traffic stops, states stay until the next `release`, however long ago they expired. Bucket names come from the caller. Among the facades only GitHub installs a `WindowLimiter` by default (`github/src/client.mbt`, `default_limiter`), over three buckets (`core`, `search`, `graphql`; `github/src/call.mbt`, `rate_limit_bucket`); OpenAI and Anthropic use `NoLimiter` and name a fixed bucket per operation family. A state lives until its reset, at most one hour after the response that set it: `release` clamps both a parsed reset (`rate_limit_headers`, GitHub's default, or any caller-supplied parser) and a 429 `Retry-After` override (bucket or account-wide block) to `max_server_wait_ms`, one hour, GitHub's longest window (#50) |
| Account-wide window (`sdk-runtime/src/rate_window.mbt`, `global_step`) | Admissions | Constant: one window start, one count, one block deadline |
| Gate waiters (`http-async/src/gate.mbt`, `SemaphoreGate`) | Tasks waiting for a permit | The caller's concurrency |
| Response streams (`http-async/src/transport.mbt`, `ClientStream`) | Body bytes | Beyond a coded body's decoder state (bounded in "Content decoding"), the transport keeps nothing between reads; the reader decides what to keep. A stream may last indefinitely while each read arrives within `read_timeout_ms` (default `timeout_ms`) |
| `Paginator::each` and `next_page` (`sdk-runtime/src/paginator.mbt`) | Pages | One page at a time. A server that always names a next page keeps the walk fetching, in constant memory; the callback stops it by raising |
| Codex child process (`codex-app-server/src/child.mbt`, `spawn`; `jsonrpc-async/src/child.mbt`, `spawn_child`, `Child::shutdown`) | stdout and stderr output | stdout is read continuously by the connection's read loop; stderr is inherited, never buffered here. The child and its pipes end with the caller's task group, and `shutdown` cancels the child after its timeout |
| The `Cookie` header (`http/src/cookie/jar.mbt`, `CookieJar::header_for`) | Cookies matching one request | The host's and its parent domains' cookies, at most `max_per_domain` each and `max_total` in all, each under 4096 bytes. The header is built per call and not kept |

## Left to the caller

Growth that follows what the caller asks for, not what the network sends.

| Structure | Grows with | Why it is not bounded here |
|---|---|---|
| Pending JSON-RPC calls (`jsonrpc-async/src/connection.mbt`, `Connection::call`, `fail_pending`; `dispatch.mbt`, `Connection::dispatch`) | Calls the caller starts and the peer has not answered | The caller decides how many calls to start and how long each may wait: an entry leaves on its response or failure, on the call's `defer` (return, `timeout_ms`, cancellation), and all at once when the connection closes or reading ends. A caller that keeps calling without `timeout_ms` a peer that keeps the connection open but never answers grows the map without end, so such callers need deadlines or a cap on calls in flight. The Codex handshake has a 10 s deadline (`codex-app-server/src/client.mbt`, `initialize_connection`) |
| Buffered response body size (`http-async/src/transport.mbt`, `AsyncTransport::new`, `max_body_bytes?`) (#48) | Response size, unless the caller sets `max_body_bytes` | The facades (`OpenAI::new`, `Anthropic::new`, `GitHub::new`) use the transport they are given, so its owner sets the limit. Every README's setup and the live tests use `max_body_bytes=64 * 1024 * 1024`; the GitHub README sends file downloads to `send_stream` on the redirect target, or to a client with a larger limit. Unset, the bound is `timeout_ms` (30 s) times bandwidth. `Decode` keeps the successful body under that same limit |
| Streamed tool-call reassembly (`openai/src/types.mbt`, `ToolCallAccumulator::feed`; `anthropic/src/tools.mbt`, `ToolUseAccumulator::feed`) | The tool-call arguments of one stream, as the caller feeds the deltas | Arguments must be whole to be parsed. Each delta is within one SSE event's bound, but nothing caps their total: a request without a token limit, or an endpoint that keeps streaming while each read meets its timeout, grows the accumulator without end. The caller feeds it, so the caller caps it, by total events or accumulated bytes; set a token limit on the request as well |
| `Paginator::collect` | `max` | The caller states how many items it wants |
| A custom `RetryDecider` (`sdk-runtime/src/retry.mbt`) | Attempts | The decider is the policy |
