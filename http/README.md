# gaato/http

Sans-IO HTTP vocabulary for MoonBit SDKs: `Request` (with a `Body` of bytes or a `StreamBody` read as it is sent), `Response`, `Headers`, the `Transport` and `BodyStream` traits, middleware, URL and form encoding (`percent_encode`, `append_query`, `form_urlencode`), a UTF-8 encoder that never aborts (`encode_utf8`), header helpers (`parse_retry_after` / `retry_after_ms`, `parse_link_next`, `is_idempotent`), a `Clock` trait (`gaato/http/clock`), `Gate` and `Timer` traits an async runtime implements so sans-IO code can hold a slot or bound a wait (`gaato/http/sync`), a retry-decision core whose policies are data (`gaato/http/retry`), host randomness for jitter and boundaries (`gaato/http/random`), a multipart writer whose file parts may stream (`gaato/http/multipart`), an incremental WHATWG-conformant SSE parser (`gaato/http/sse`), an RFC 6265 cookie jar (`gaato/http/cookie`), and a scripted `FakeTransport` / `FakeClock` for tests (`gaato/http/mock`). No dependencies; runs on wasm-gc, wasm, js and native.

The SSE parser bounds one event at `max_event_bytes` (16 MiB by default): the raw bytes of its `data` lines, of the `event` and `id` lines in effect (the `id` persists into later events, so it counts against each of them until replaced), and of the line being read. A stream that never ends a line, or never sends the blank line that ends an event, fails with `HttpError::Protocol` instead of growing memory without bound. Events completed before the oversized one are still delivered: when they arrive in the same chunk, `SseParser::feed` returns them and the next `feed` (an empty chunk is enough) or `finish` raises; `each_event` dispatches them and then raises without reading further. Pass `max_event_bytes` to `SseParser::new` or `each_event` to change it.

`Url` parses, normalises and resolves URI references by RFC 3986 (non-ASCII hosts are refused; pass the IDNA `xn--` form). `follow_redirects`, or the `redirects` middleware step, follows 301/302/303/307/308 up to `max_redirects` (10 by default), rewriting POST to GET where browsers do, stripping credentials when the origin changes and refusing `https` to `http` unless `allow_downgrade` is set. `follow_redirects_stream` does the same for `send_stream`, closing each redirect body unread. A redirect that would resend a stream body already sent is refused, as Fetch does. Nothing follows redirects unless you add the step.

`CookieJar` stores the `Set-Cookie` headers of responses and builds the `Cookie` header of later requests, reading the time from a `Clock`. It keeps at most 50 cookies per domain and 3000 in all (both adjustable), evicting expired cookies first and then the least recently used, and ignores a `Set-Cookie` over 4096 bytes. It has no Public Suffix List: it refuses a single-label `Domain` such as `com`, and `CookieJar::new(clock, is_public_suffix=...)` takes a lookup to refuse more. `HttpOnly` cookies are sent and `SameSite` is recorded but not enforced, as in other HTTP clients. `@cookie.cookies(jar)` is the middleware step: put it after `redirects` in the `send_with` array so that every redirect hop stores and sends its own cookies.

`HttpError` separates a failed connection (`Connect`: nothing was sent) from a `Timeout` or `Network` failure in a later `Phase` (`Pool`, `Dial`, `Write`, `Head`, `Body`, or `Unknown`) and a malformed message (`Protocol`); `HttpError::is_unsent` says whether a non-idempotent request may safely be sent again.

`RetryRule::decide` turns one failed attempt (a response status or an `HttpError`) into `Wait(ms)` or `Stop(reason)`: which statuses and failures are retryable and for which methods, an override header such as `x-should-retry`, `Retry-After` / `retry-after-ms` with a cap, exponential backoff with no, full or proportional jitter, and a remaining time budget. It decides only; it never sleeps or sends, and the caller injects the random number, the clock reading and the budget. The rule holds no vendor defaults: presets live in the layers that own the policy, such as `gaato/sdk-runtime`.

An SDK built on this module never imports an async runtime: the caller passes a `Transport` and a `Clock`, for example from `gaato/http-async`.

Unofficial and experimental. Source, issues and design notes: https://github.com/gaato/mbt-sdk
