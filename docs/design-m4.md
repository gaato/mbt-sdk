# 設計メモ — M4: 生成と自動化(試作)

M4 の目的は「上流 spec の変更と MoonBit 言語の変更を、人手なしで吸収できる経路」を端から端まで通すこと。ジェネレータの対応範囲は狭くてよいが、**対応していないものを黙って `Json` に落とさない**(oas2moon の失敗)。

## パイプライン

```
openai/spec/openai.yaml ─▶ overlays/fix.yaml ─▶ overlays/moonbit.yaml ─▶ 正規化 ─▶ IR(JSON) ─▶ MoonBit 出力
        (vendoring)          (上流の修正)         (x-moonbit-*)        tools/gen/        openai/src/gen/*.mbt
```

- 実装は Python(`tools/gen/`、`uv run` で依存ごと実行。依存は `pyyaml` と `jsonpath-rfc9535` まで)。MoonBit で書かない理由: ジェネレータ自体が言語変更で壊れる対象になるのを避ける。
- 出力は `openai/src/gen/`(パッケージ `gaato/openai/gen`)。先頭行は `// GENERATED by tools/gen — DO NOT EDIT.`。出力は決定的(同じ入力からバイト単位で同じ結果。キー順は spec の出現順)。生成物はコミットする(利用者は Python なしでビルドできる)。
- 実行: `uv run tools/gen/main.py --spec openai/spec/openai.yaml --overlay openai/overlays/fix.yaml --overlay openai/overlays/moonbit.yaml --out openai/src/gen --package gaato/openai/gen [--check]`。`--check` は書き込まずに差分があれば非 0 で終わる(CI 用)。overlay の適用は `tools/apply_overlay.py` の関数を再利用する。

## 対象の選び方

`x-moonbit-include: true` が付いた操作と、その要求/応答スキーマから `$ref` で到達できるスキーマだけを生成する。M4 の対象は `listModels` `retrieveModel` `createEmbedding` の 3 操作。`createResponse` は対象外にする(`moonbit.yaml` から include を外し、理由を `docs/design-m4.md` の「未対応」に書く): 到達スキーマが数百あり、discriminator なしの `oneOf` が多く、M4 の範囲を超える。

## 型の写し方(規則)

| OpenAPI | MoonBit |
|---|---|
| `type: object` + `properties` | `pub(all) struct`。required かつ非 nullable → `T`、required かつ nullable → `T?`、非 required かつ非 nullable → `T?`、非 required かつ nullable → `@sdkjson.Presence[T]` |
| `allOf` | オブジェクト同士なら properties / required を併合して 1 つの struct。それ以外の組み合わせは診断エラー |
| `type: string` + `enum`(応答に現れる) | open enum: 既知の値 + `Unknown(String)`。デコードは `@sdkjson.open_string` |
| `type: string` + `enum`(要求にだけ現れる) | 閉じた enum + `Custom(String)`(新しい値を SDK の更新なしに送れる) |
| 値が 1 個の `enum`(`x-stainless-const` など) | フィールドを生成しない。エンコード時は定数を書き、デコード時は検証しない |
| `type: integer` | `Int`。`format: int64` または `x-moonbit-type: Int64` なら `Int64`(JSON 数値から整数性と範囲を検査して読む) |
| `type: number` | `Double` |
| `type: array` | `Array[T]` |
| 名前付きのプリミティブスキーマ(`components.schemas.X` が `type: string` など) | `x-moonbit-type` があればその名前の newtype(`pub(all) struct X(String)`)、無ければ素の型に展開 |
| `oneOf` / `anyOf`(discriminator なし) | 各候補が JSON の形(string / number / boolean / object / array、array は要素の形まで)で一意に区別できるときだけ enum を生成(バリアント名は `x-moonbit-variants` か、形から `Text` `TextArray` `IntArray` `IntArrayArray` のように機械的に付ける)。`anyOf: [string, enum-string]` は「既知の値つきの文字列」として `String` に畳む。区別できなければ診断エラー |
| `oneOf` + `discriminator` | M4 では未対応(診断エラー) |
| `additionalProperties: true` / スキーマなし | `x-moonbit-json: true` が明示されているノードだけ `Json`。無ければ診断エラー |

診断エラーは「スキーマの JSON ポインタ・理由・取りうる overlay の指定」を 1 行ずつ出し、1 件でもあれば何も書かずに非 0 で終わる。

## 生成するもの

- 各 struct / enum に `ToJson` と `@json.FromJson` の実装(`@sdkjson.ObjBuilder` / `field` / `opt_field` / `presence_field` / `open_string` を使う)。未知のフィールドは無視。
- 各操作に、IO を持たない 2 つの関数: `<op>_request(params...) -> @http.Request`(相対 URL、メソッド、JSON 本文)と `<op>_decode(@http.Response) -> T raise @runtime.SdkError`(JSON 不正・必須欠落は `Decode`)。送信は手書き層が `@runtime.Client` で行う(sans-IO)。パスパラメータは RFC 3986 の unreserved 以外を percent-encode する。
- `openai/src/gen/` は `gaato/http` `gaato/sdk-runtime` `gaato/sdk-runtime/json` だけに依存する。

## 手書き層との関係

M3 の手書きの `list_models` / `retrieve_model` / `create_embeddings` は、内部を生成された `<op>_request` / `<op>_decode` に差し替える(公開 API は変えない。生成型 → 手書きの公開型への変換は手書き層に置く)。M3 のテストがそのまま回帰テストになる。`create_response` と `stream_response` は手書きのまま。

## CI(ファイルを置くだけ。M4 では push しない)

- `.github/workflows/ci.yml`: push / PR。コンテナ `ghcr.io/gaato/moonbit:<固定版>` で AGENTS.md のゲート一式(js テストのために Node を入れる)、`uv run tools/gen/main.py ... --check`、overlay の適用確認。
- `.github/workflows/canary.yml`: 毎日。コンテナ `ghcr.io/gaato/moonbit:latest`(上流の最新リリースに自動追従)で同じゲート。失敗は「言語側の変更で壊れた」の合図。
- `.github/workflows/spec-watch.yml`: 毎日。上流 spec を取得して sha256 を `spec/SOURCE.md` と比べ、変わっていたら vendoring を更新 → overlay 適用 → 再生成 → ゲート → PR を作る。ゼロ件マッチ / no-op の overlay action は PR 本文に載せる。
- リリース(`moon publish`)の自動化は置かない: mooncakes の認証情報の扱いを gaato が決めてから。手順だけ `docs/release.md` に書く。
- どの workflow もこの段階では未実行。`actionlint` が使えれば通す。アクションはコミット SHA で固定する。

## M4a の判断

- component schema の型名は spec の名前を UpperCamelCase に正規化する。匿名 object / enum / union は「親型名 + field 名」で命名し、操作直下なら operationId に `Request` / `Response` を付ける。JSON field と operationId は lower_snake_case にし、MoonBit の予約語は末尾に `_` を付ける(`type` → `type_`)。
- enum / union variant は値または JSON shape から UpperCamelCase にする。shape 名は `Text` / `Int` / `Number` / `Bool` / `Object` とし、array ごとに `Array` を足す。`x-moonbit-variants` があれば spec の title より優先し、重複名は診断にする。`CreateEmbeddingRequest.input` は overlay で `Text` / `TextArray` / `IntArray` / `IntArrayArray` に固定した。
- schema と property の `description` は改行と連続空白を単一空白へ畳み、生成する public item の `///|` doc comment にする。description が無い型・関数には役割を示す定型文を入れる。
- 出力順は path、component、property、enum value の spec 出現順を保つ。IR の JSON dump もこの順を保ち、MoonBit 出力は `moonfmt` を通した結果を比較・保存する。
- request のみに現れる string enum は既知 variant + `Custom(String)`、response または request/response の両方に現れる enum は既知 variant + `Unknown(String)` にする。「両方」は受信時の前方互換性を優先して open enum とした。
- 単一値 enum は生成 struct の field から除き、encode では定数を必ず書き、decode では存在・値を検証しない。これにより fixture が discriminator 的な定数 field を省略していても他の必須 field は厳密に検証する。
- `anyOf: [string, enum-string]` は任意の model ID を送れる意味を保持するため `String` に畳む。named primitive は annotation 無しなら基底型へ展開し、`x-moonbit-type` があれば annotation 名の newtype にする。field の `x-moonbit-type: Int64` と `format: int64` は newtype ではなく `Int64` override とする。
- untagged union の array shape 判定は要素を全件検査する。空 array は要素 shape を判別できないため decode error とする。今回の embedding input は upstream が `minItems: 1` なので契約内である。
- `additionalProperties: false` は閉じた object の宣言として受理するが、未知 response field は通常どおり無視する。schema-less object、bare `additionalProperties: true`、typed map は M4a では診断にし、意図的に生 JSON を保持する node だけ overlay の `x-moonbit-json: true` で `Json` にする。今回の3操作には `x-moonbit-json` は付けなかった。
- request builder は path parameter の後に JSON body があれば生成 request 型を `body` として受ける。success response は 2xx の `application/json` を使い、複数ある場合は同一 schema のときだけ受理する。
- path parameter は UTF-8 byte ごとに RFC 3986 unreserved (`ALPHA / DIGIT / - . _ ~`) だけを残し、それ以外を大文字16進で percent-encode する。
- generator が管理するのは先頭が `// GENERATED by tools/gen — DO NOT EDIT.` のファイルだけとした。`--check` は書き込まず、欠落・内容差・不要になった generated file のいずれでも exit 1、schema/overlay/format の診断は exit 2 とする。手書きの `*_test.mbt` は削除・上書きしない。
- `--ir-out` は診断が0件のときだけ dataclass IR を JSON で書く。診断が1件でもあれば IR、MoonBit、既存出力のいずれも変更しない。
- generated `Model` は spec の required をそのまま必須にし、手書き API の `Model.created` / `owned_by` へは `Some` で変換する。手書き `EmbeddingRequest.input` は生成 union の `TextArray` に写し、公開 API に無い `encoding_format` は送らず upstream default に任せる。
- generated embedding body は spec の property 順 (`input`, `model`, ...) だが、手書き API の M3 回帰テストは既存の byte-level body 順 (`model`, `input`, ...) を契約としている。手書き変換層は generated request から method / URL / content-type を受け取り、body だけを従来順で再構築して公開挙動を変えない。
- JSON number の `Int64` decode/encode、untagged array shape probe、percent-encoding、HTTP body の decode-to-`SdkError` は生成 package の private helper とした。M4a では runtime の public API を増やさない。
- overlay 適用は `tools/apply_overlay.py` の `load` / `apply` を import して再利用する。M4a の3操作では言語非依存の upstream spec error は見つからなかったため `openai/overlays/fix.yaml` は追加しない。

## 未対応

- `createResponse` は M4a の include から外した。request body と JSON / event-stream response から到達する component schema closure は **115 schemas**、その closure 内で discriminator の無い `oneOf` は **11 nodes** あり、object 同士を JSON shape だけで区別できない union と discriminator union を含む。これらに個別の raw `Json` annotation を大量に付けるのは「未対応を黙って Json に落とさない」という目的に反するため、discriminator と object union の方針を決める後続 milestone へ送る。
- discriminator 付き union、同じ JSON shape の untagged union、recursive schema、query/header/cookie parameter、typed map、複数の異なる success response schema は診断にする。対応するまでは対象 operation を include しない。
